Checked on 17 Oct 2026, from Claude Code's Chrome docs, HubSpot's help pages and ~/.claude.json:

- Start the session with claude --chrome. It uses whatever login Chrome holds, so a HubSpot "Log in as" session in Chrome means the agent acts as that user. Start prompts check the page for the "You are temporarily logged in as" banner and the account menu's name first, and stop otherwise.
- claudeInChromeDefaultEnabled is true on this PC, so every Claude Code session connects to Chrome. On Windows, two sessions that use Chrome can break each other's connection (a named pipe conflict), so close the others first.
- Auto mode pauses after 3 blocked actions in a row or 20 in all (not configurable). A JavaScript alert or confirm blocks the extension until a person dismisses it. The extension can go idle in long runs; /chrome > Reconnect extension.
- HubSpot's workflow Test is a simulation ("No actual actions will be executed"), but its Send preview sends real emails to the user's own inbox. A draft marketing email cannot be picked in a workflow's Send email action; a placeholder action saves, and blocks turning the workflow on.
- Recurring dashboard and report emails go only to HubSpot users. View-Only seats are free.
- Agent Hub (HubSpot's help pages, read 17 Oct): Create workflow offers From scratch, From template, With AI and With new builder (Beta); AFK runs build From scratch in the classic tool. New-builder workflows list only in Agent Hub's Workflows tab, and its pages document no delay until a date property, no manual enrollment (so no Manual Test) and no Manage access. A deleted new-builder workflow cannot be restored, and File > Convert to new builder is permanent. A Breeze Assistant chat prompt creates a workflow (Off) or a record at once. Agents need the account-wide Files data AI setting (off in EO's portal) and HubSpot Credits; AI workflow actions and smart properties spend credits too.

- HubSpot's AI runs by itself when some pages open, with no click (seen in EO's portal, 17 Oct 2026 AFK run): the custom report builder's Save report dialog fills the Description box with an AI text (pink loading lines, then "Generate again"); typing over it still leaves an "AI" badge on the saved report's Description. Opening a deal record page generates its AI "Record summary" ("Generated <date>"). So an AFK prompt that says "no AI" cannot keep the report Save dialog clean, and the run must never open a record page; read records with the HubSpot MCP. HubSpot's Credits page: account name > Account & Billing > Usage & Limits > HubSpot Credits > Manage usage by feature (its help page does not say whether these two features spend credits).
- Opening a saved report in the report viewer (reports-list/<portal>/<id>) can also show an AI insight under Report summary by itself ("AI-generated content may be inaccurate"), seen 18 Oct 2026 on report 446020405; the renewal report 446222937 showed none. Read report filters by hovering the "Filters (n)" chip (it lists "Active Filters (ALL)").
- HubSpot workflow Test on a real deal in the trigger's pipeline and stage opens in Automatic mode with "Expected to start automatically" and four start checks; that is the proof a workflow enrolls by itself (18 Oct 2026, Dues due on test deal 66214847534).
- The claude.ai HubSpot connector: an allow rule (/permissions) only lets Claude Code call a tool; HubSpot write access comes from the connector's own sign-in. On 18 Oct 2026 get_user_details showed every CRM write as REQUIRES_REAUTHORIZATION four times, even after Khôi reconnected in claude.ai, and then every call failed with "needs you to sign in again (run /mcp to re-authenticate)": a running session keeps its old connection, so after a reconnect run /mcp (or restart) before relying on it. After Khôi's /mcp, deal, contact, company, task and list writes read AVAILABLE (tickets, notes, line items, emails still REQUIRES_REAUTHORIZATION). Right after one connector write to live HubSpot, the auto-mode classifier blocked even tabs_context_mcp [Modify Shared Resources] (18 Oct 2026).
- 18 Oct 2026: the auto-mode classifier also blocked manage_custom_properties (creating a deal property in EO's live HubSpot) even after Khôi's "FULL access ... do whatever necessary"; a user message does not lift it, only an allow rule does. GitHub Actions of EO-Vietnam/altai-hubspot-sync are invisible from here: gh is signed in as a personal account (404) and Chrome is not signed in to GitHub (Page not found); read the latest sync run on eochapterhubspotrollout.com/admin/altai-sync (Chrome is signed in there).
- 29 Oct 2026, building workflow 1912224299: in the Edit record panel, close the value list with Escape after picking a team; a click on "blank" space once added a second, wrong team (Systems Architecture and Integration Team) and clicking a field label opens that field's dropdown.
