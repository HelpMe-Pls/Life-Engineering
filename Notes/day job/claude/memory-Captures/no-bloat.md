Keep only what is worth having long-term. Memory notes hold decisions, standing rules, non-obvious lessons and pointers to where detail lives, never a session's build log, record ids, test outputs or word counts (those belong in the session reports, scopes and proof folders). Delete a session's scratch files when done.

**Why:** a project note had grown to 7,900 words of logs that other files already held; Khôi asked not to bloat the machine with unnecessary tracking.

**How to apply:** before adding to a note, ask whether a later session needs it and cannot find it elsewhere; prefer one pointer over a copy. AFK prompts that say "keep the memory note current" mean a short dated line, not a log ([[afk-prompts-keep-files-current]], [[sow1-priority2-scoping]]).
