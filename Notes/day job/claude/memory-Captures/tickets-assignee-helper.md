In Sprint 38 they sit in a `.t-end` group with its Status select; its Copy as Markdown adds `**Assignee**`.

Status chips (Sprints 39, 40 and later): `<span class="status doing" data-card="N">DOING</span>` is a button with a ▾; a click opens a menu of TO DO / DOING / WAITING / DONE (keyboard works too) and the choice saves at once. The card's `<article class="ticket">` also carries `waiting` or `done` (orange or green left edge; DONE chip `#14a06f`). Sprint 38 keeps its own per-browser Status select (localStorage, not the file); the user asked only about the 39/40 chips.

**Why:** the user wants every edit to a tracker to persist across browsers (Edge default, Firefox Developer Edition 158 too), the helper to run only while a tracker is open in some browser, and new trackers added to the folder to "just work".

**How it works:** the page posts changes to the helper `%LOCALAPPDATA%\Edge8\tickets-helper.pyw` (stdlib Python v2 run by pythonw via the WindowsApps alias, so two processes: launcher + runtime). It rewrites only `data-assignees`, status chips and the card's status class, only in `.html` files directly inside Tickets (not subfolders), only for `Origin: null`/`file://`, and only if the file's `<title>` matches the page's `document.title` (whitespace-collapsed since 2026-10-07; before, a title with a double space, line break or attribute was refused on every save). Each open tracker holds a WebSocket to `/presence`; `/ping` reports `pages`. The helper exits 5 s after the last tracker closes (20 s if none ever connects), both processes gone. Pages start it through `edge8-tickets://start` (`HKCU\Software\Classes\edge8-tickets`): Chrome/Edge follow the link in a hidden iframe when the tracker opens, but refuse ("user gesture is required") if there was no click since their previous start; Firefox follows it only as a top-level navigation from a click (iframes never work there). So the first click or edit on the page starts it, and Firefox keeps the buttons live meanwhile. Without the helper, Chrome/Edge can save via File System Access after the user picks the folder.

**Browser prompts for the link (checked 2026-10-07):** Chrome/Edge's "Always allow file:// to open links of this type" is stored per origin `file://`, so one tick covers every tracker, new ones included; neither browser had it ticked yet. Firefox stores "Always allow this file to open edge8-tickets links" per file URL (its permissions.sqlite held it for Sprint 40 only), so each new tracker would ask once. At the user's request (2026-10-07) the Developer Edition profile `%APPDATA%\Mozilla\Firefox\Profiles\ndn653q8.dev-edition-default\user.js` sets `network.protocol-handler.external.edge8-tickets` to true (effective from the next Firefox start). Tested: that pref alone lets a click on a never-allowed tracker start the helper with no prompt (Firefox requires the click's user activation for this shortcut); without it the prompt waits.

**Testing note:** on Windows a fetch to a closed localhost port takes ~2 s to fail, so for ~2 s after a tracker opens the page does not yet know the helper is down. In Firefox a click elsewhere on the page in that window starts nothing (a click on an assignee or status still does). Tests must wait about 6 s before the first click. A tracker open in the user's own browser joins any helper a test starts (its page connects as soon as the helper answers), so a test's "closing stops the helper" check fails while one is open (seen 2026-10-07): read `/ping`'s `pages` and treat a non-zero count as a join, not a fault.

Auto mode blocked a Startup-folder auto-start ("unauthorized persistence"). Never add sign-in auto-start without asking again.

**How to apply:** model a new tracker on the newest one in Tickets: keep its assignee and status CSS, the `<script>` starting "Assignee and status picker" verbatim, one `<span class="assignee" data-card="N" data-assignees="">` at the end of each card's `.t-fields` (class exactly `assignee`), and `data-card="N"` on each status chip (`class="status KEY"`, `status` first, label only inside). Pre-fill nobody unless asked. A new file built this way (new name, title and card ids) was tested on 2026-10-07 in Edge, Chrome and Firefox and saved through the installed helper. `data-card` values are ids, not positions: when merging or renumbering cards in a tracker that may be open in a tab, keep each surviving card's id and drop the others, never reuse an id for different work (a stale tab saves by id; a dropped id is refused with "Reload the page"). Sprint 40 showed cards 1–9 with ids 1, 3, 6, 10, 11, 12, 13, 14, 15 on 2026-10-08 (Cards 6–7 added on 2026-10-07 and Card 8 on 2026-10-08 by inserting new lines before the parked list with a check-then-write script, their status and assignee saves tested through the installed helper; Card 9, id 15, "Review Dave's Trends, FAQ and Melbourne plan", was added by another session at 13:19 the same day; Card 10, id 16, the EO Vietnam chapter dashboard template, was added DONE on 2026-10-09). Other sessions edit the same tracker, so a script must read the current ids, never assert a hard-coded list, and must keep cards it did not write. The page script holds one literal `</span>` in a JS string, so a tag-balance count must look at the body before `<script>` only. Edits to existing trackers must keep the user's live picks: patch the files in place, never regenerate them from an older copy. To uninstall: delete that registry key and `%LOCALAPPDATA%\Edge8`, and remove the picker script from the trackers too (a browser told "Always allow" would otherwise hand the dead link to Windows, which pops "Get an app"; see [[never-pop-windows-dialogs]]).
