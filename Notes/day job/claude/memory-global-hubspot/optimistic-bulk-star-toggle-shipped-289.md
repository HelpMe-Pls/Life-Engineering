Made the /admin wave-board bulk **"Toggle chapter prioritization (N)"** button optimistic. Shipped to prod: feature `feat/bulk-star-optimistic-ui` → dev via **#288** (`5d701a6`), promotion **#289** dev→main (`6a323c9`), Vercel prod deploy success + public smoke green.

**Design:** new `ChapterStarProvider` shared optimistic-override store (`app/admin/components/ChapterStar.tsx`) that `ChapterBulkBar` writes and each `ChapterNameCell` reads (the bulk bar owns no row state, so a shared context is the only seam to flip sibling stars in place). Flip happens in `useActionRunner`'s urgent `prepare` slot; server loop + `router.refresh()` run in background; selection + overrides clear on the pending-settle frame; failure reverts. `starById` (server snapshot) passed from `page.tsx` as the flip base.

**KEY BUG the adversarial review caught (I'd dismissed it as "rare, self-heals" — it does NOT):** having TWO optimistic layers for one entity's star — per-cell `optimisticStarred` (single-row) vs the shared `override` (bulk) — makes them diverge. A single-row star (no `router.refresh()`) leaves `optimisticStarred=true` while `lastInitial` stays false; a later bulk toggle predicts from the stale `starById` and flips the DB the opposite way; after refresh `useAdoptServerInitial` sees `initial===lastInitial` and **does NOT adopt**, so the star is STUCK showing the wrong value. **Fix: unify — the single-row board toggle ALSO writes the shared override (one optimistic source), plus a per-cell effect keyed ONLY on `base` that drops the override when the cell adopts a changed server value.** Detail page renders no provider → `useChapterStarStore()` null → per-cell path unchanged. Refines [[async-transition-state-defers-until-settle]].

**FOLLOW-UP shipped 2026-07-15 (#290→dev, #291 dev→main `cd8df59`, prod-verified):** diagnosed "bulk reconcile takes ≥5s on prod, ~1–2s on preview." Root cause = every bulk action (star/move/subwave/delete) ran a per-chapter SEQUENTIAL loop (`select`+`update`/`delete`+audit = **3N serial Supabase round-trips**) then `router.refresh()` re-rendered the whole 228-row board. Prod≫preview is **cold start** (both `sin1` + same shared Supabase project ⇒ identical per-RT latency; the actively-clicked preview stays warm; `@sentry/nextjs`+OTel makes cold starts heavy). Couldn't confirm to the ms — Vercel CLI here isn't authed + no Vercel MCP; cheap check = click twice, fast 2nd ⇒ cold start. **Fixes:** (1) batched all four actions to set-based `.in()` queries + new `writeAuditBatch` helper (`lib/audit/log.ts`) = ~3–4 RTs vs 3N; (2) **eager selection-clear** for EVERY bulk op (checkboxes uncheck + bar dismisses in the urgent prepare) via one `runBulkOp` helper; delete/move/subwave show a slim in-progress banner (`busyLabel` state, cleared in the async task NOT an effect — avoids react-hooks/set-state-in-effect + refs-in-render). **3-lens adversarial review (capped at 3 agents per user) caught 3 real bugs, all fixed:** (a) star's two grouped updates aren't atomic → audit each group RIGHT AFTER its own update commits (not once at end) so a committed flip is never unaudited; (b) a REJECTED action (requireAdmin throwing on expired session) wedged the banner forever → `runBulkOp` awaits in try/catch, always clears the banner; (c) eager-clear lost the selection on error → `restore(ids)` re-selects on any failure so retry is one click.
