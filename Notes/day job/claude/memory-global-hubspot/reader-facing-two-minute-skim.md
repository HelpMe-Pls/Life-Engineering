**Why:** these docs go to Dave, EO and the group. A bare number, a count of records instead of people, a quote given to the wrong speaker, an unchecked weekday, an undefined unit, an unexplained word or a local reference makes the reader stop and ask, and that defeats the skim.

This memory holds only the Edge8 layer. ⚠ **Test each change to the rule before you report it:** give a cold reader 11 to 16 sample requests, with their outputs (the chat reply, the document, the steps in it), and ask for each "TWO READINGS". On 12 Oct, each of the first three rounds found real conflicts that a self-read had missed: the path ban against "give me its path", "ONE line" against "one line per part", `EXACT_MATCH` in code acting as a trigger, and one-line steps that broke exact field names in a spec.

**Triggers (operator, 2026-10-12):** without a trigger, the rule covers the read-only texts that its Goal describes. A trigger switches it on for each text that the trigger is about and that the request makes or changes, a pull request body, a spec, a setup guide and a handoff note included. One trigger is `2 minutes` in any form or with a typo (`2-minute`, `two minutes`, `2 mins`). The other is an all-caps EXACT, EXACTLY, ACTUAL or ACTUALLY.
- **Never covered:** a chat reply, what a script or wizard prints, code, a commit message, or a file that sets an AI agent's rules (a CLAUDE.md, a skill, this memory).
- **About, not anywhere:** "fix it, open a PR and tell me EXACTLY why" switches nothing on for the PR body, because EXACTLY is about the chat answer.
- **A kind that only a trigger brings in** keeps its own file type and place. Rules 3, 4, 5 and 9, and the parts of rules that name other kinds, do not apply to it. A skill's, a tool's or the project's format wins, such as "Closes #12" in a PR. A warning and "What to do" appear only if the text has them.
- **Part of a text:** when the request adds to or changes part of a text, the rule covers only that part. It covers the whole text when the operator asks for that, or when a trigger is about the whole text ("make sure the doc is a 2-minute skim"). With or without a trigger, the Goal's kinds stay covered.
- **Both rules, each on its own output:** the skim rule alone shapes the document. An all-caps word adds only that the document lists every step or item the request puts in it (EXACT means complete there, and the rule says this list wins over "precise, not exhaustive"). A list that breaks rule 9's word limit goes on an attached page. The chat reply is one line, and each file made or changed gets its path on its own line. Round 3 of the cold reads removed an earlier "one line per step inside the document": it fought exact field names in a spec and the operator's "one-line rule only for chat answers".
- **Ordinary uses:** `2 minutes` as the time of a build or a wait. Either trigger inside a name, code (`EXACT_MATCH`) or words quoted from someone else. When `2 minutes` is about a text that the rule does not cover (the chat reply, a skill), it keeps its plain meaning: that text reads in no more than 2 minutes.
- **Paths:** the text bans only a file path or step that works only on this machine, so a PR or spec keeps its repo paths.
- **Why:** the operator set this after two side-agent notes. First, EXACTLY could turn a document into one-liners. Then a setup guide asked for with EXACTLY fell under neither rule. Three cold readers then tested 11 to 16 sample requests against the text. See [[how-it-works-answer-in-one-plain-line]].
